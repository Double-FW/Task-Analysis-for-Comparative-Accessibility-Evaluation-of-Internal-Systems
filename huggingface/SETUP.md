# Weekly task-analysis dataset sync

Destination: https://huggingface.co/datasets/GarethFW/Task_Analysis_for_Comparative_Accessibility_Evaluation_of_Internal_Systems

1. The workflow already names `GarethFW/Task_Analysis_for_Comparative_Accessibility_Evaluation_of_Internal_Systems` as its destination. No repository variable is required. If an existing `HF_DATASET_ID` variable is present, it must have exactly that value; review it on [Actions variables](https://github.com/Double-FW/Task-Analysis-for-Comparative-Accessibility-Evaluation-of-Internal-Systems/settings/variables/actions). A wrong override stops publication.
2. Open https://huggingface.co/settings/tokens and create a Fine-grained/Custom token. Under repository permissions select only `GarethFW/Task_Analysis_for_Comparative_Accessibility_Evaluation_of_Internal_Systems` and grant read and write access. Leave unrelated permissions unticked. Copy the generated token beginning `hf_` privately.
3. Open [Actions secrets](https://github.com/Double-FW/Task-Analysis-for-Comparative-Accessibility-Evaluation-of-Internal-Systems/settings/secrets/actions). Add or update `HF_TOKEN` with that generated token, using an underscore. Do not paste the dataset name into the token field or share the token in chat.
4. Open [the workflow](https://github.com/Double-FW/Task-Analysis-for-Comparative-Accessibility-Evaluation-of-Internal-Systems/actions/workflows/huggingface-sync.yml), choose Run workflow on main, and inspect the new run. Confirm successful publication and the destination Files tab before reporting the sync complete.

Schedule: Monday 10:43 UTC (10:43 UK winter, 11:43 UK summer). GitHub may delay scheduled runs or disable schedules in inactive public repositories. Manual Run workflow is available.

The source must remain public and the existing destination must be initialised. GitHub’s automatically supplied read-only token authenticates the public-source check; no additional GitHub token is needed. HF_TOKEN is supplied only to the publishing step. Only eight managed output files are committed atomically against the destination revision. Unrelated files, including `.gitattributes`, and destination visibility are preserved. A no-change run creates no dataset commit.

The export contains eight complete maintained documents, fourteen methodology sections as an alternative view, and ten activities preserving all twenty prompts and the complete folder activity file. Source context, evidence limits, original dates and rights are retained. The assessment record and fictional calculations are illustrative, not completed studies or employee evidence. All source GitHub links are checked for preservation. Linked external bodies are not copied. No test/audit report is published in source or dataset; diagnostics stay in workflow logs. Provenance and schema describe source origin, roles and format only.

Three navigation files (folder README, RAG index and coverage register) are checked and listed in provenance rather than exported as substantive records. The source allowlist must be exactly classified as document, activity, navigation or licence. A new committed file anywhere outside .github/, scripts/, tests/ and huggingface/ stops publication until its role is reviewed. Those directories are reserved for implementation/setup, not guidance. New content is not uploaded automatically: this prevents both silent omission and unreviewed publication.

The allowlist is explicit. New files, changed licences or a changed destination require review before changing configuration. Missing/dirty approved source, invalid structure, a wrong dataset or a token field containing the dataset name stops publication. Do not confuse these checks with a participant study, employee assessment, legal review or model evaluation.

For local checks, install `huggingface/requirements.txt`, then run `python scripts/export_huggingface.py --check-only` and `python -m unittest discover -s tests -v`. Build with `python scripts/export_huggingface.py --output /tmp/task-analysis-preview --dataset-id GarethFW/Task_Analysis_for_Comparative_Accessibility_Evaluation_of_Internal_Systems`. Regression tests use a simulated destination and no real credentials.
